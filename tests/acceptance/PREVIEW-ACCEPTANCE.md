# 预览验收方法（只设计，不落地）

范围前提：Tim 2026-09-17 裁剪后，预览 = **模板效果预览**（只画文字层 + 背景一张静帧），
不解码视频、不建代理、不做后台分段编码、不出声、软件内不做时间线编辑。
所以**"预览与成片是否一致"要重新定义**：不是"画面一样"，而是**同一套排版 + 同一段文字**。

## 面 1：预览文字与成片文字是同一套排版

**自动判（优先做前两条，它们是硬证据）**

1. **对象层同一性（最强、最便宜）**：预览与导出**都从同一个 `LayoutSurface` 取放置表**。
   验收脚本各自拿到 `placements`（role / x / y / size / 字体名 / 颜色）后**逐字段比对**；
   任何一项不同即 FAIL。这一条把"两套排版代码"从根上排除，且不需要像素。
2. **像素层一致性（复用现有探针，不另造）**：沿用 `accept_range.py --pixels` 那套口径——
   分带（`BANDS`）、半高（0.075 / 紧带 0.045）、半宽 0.45、ink 阈值 0.006、噪声上限 0.015。
   - 取一个词，**成片**在中文相位抽帧（verifier 已有的 `gray_frame`）；
   - **预览**在同一像素尺寸（建议 320×180，与门禁现有夹具同尺）下**离屏渲染**同一词、
     同一相位，抽帧；
   - 两条路径都按**画布比例**分带（预览 320×180 与成片 1920×1080 是同一比例，带位置可比），
     逐带比较 ink 是否存在、以及两帧的**带内均值差**（沿用 2/255 容差）。
   - 只比**文字层所在的带**（english/phonetic/meaning/title/subtitle/footer）；背景带不参与，
     因为成片背景是视频、预览是静帧，两者本来不同。
3. **内容层**：预览画出的字符串必须等于词表期望（`load_expectations` 的 word / phonetic /
   meaning），且与同一批次 SRT 04/05 轨逐字一致——预览若把"中文带词性"当无词性画，这里会红。

**只能人眼看（不许自动化冒充）**：字体观感、字重/描边/阴影的美感、字距与换行的"看着舒服"、
颜色在真实屏幕上的感觉、多词切换时的观感。自动判只能给"是同一套排版、同一段文字"，
**不能替 Tim 说"好看"**。人眼项在报告里单独列，写"未判"。

## 面 2：打开工程 → 看见文字的时延与资源

**口径（固定协议，别每次换个说法）**

- **时延**：从**进程启动**（记录 `spawn` 时刻）到**画布上第一个文字像素出现**——
  用面 1 的同一套探针：按 ~50ms 轮询离屏画布，第一次在 english 带读到 ink ≥ 0.006 即停表；
  同时记"首个非背景像素"作为备选口径（背景静帧本身要画出来，两者之差=背景绘制开销）。
  **报 p50/p95（≥5 次冷启动）**，不要单次数字。
- **资源**：同一次运行里取 **峰值 RSS**（Windows 用 `GetProcessMemoryInfo` 的
  `PeakWorkingSetSize`，或 `psutil` 的 `memory_info().peak_wset`）与**空闲 30s 的 CPU 时间**
  （两次 `cpu_times()` 之差 / 墙钟，即"看着不动时占多少核"）。另外记**打开后 10s 内的线程数**，
  用于发现"后台还在偷偷跑"。
- **红线（必须自动判，因为它们就是这次裁剪的理由）**：
  - 预览进程**不产生任何 ffmpeg/解码子进程**（`subprocess` 审计钩子记 `Popen` 事件，
    期望为空；比"看代码"可靠）；
  - **不打开任何音频设备**（审计钩子里不得出现音频相关模块加载 / 设备名）；
  - 不打开工程里的视频文件：把背景静帧换成**同名但不可解码**的文件跑一次，预览必须照常出字
    （证明它真的没解码视频），这条是"不解码"的行为证据；
  - **重绘按需**：位置/样式不变时连续 10 次重绘请求 → 画布实际重绘次数 ≤ 1（接口留计数器）。

**能自动判 / 只能人眼**

| 项 | 判定方 |
|---|---|
| 同一 `LayoutSurface` 放置表逐字段一致 | 自动 |
| 文字带 ink 存在 + 与成片帧均值差 ≤ 2/255 | 自动 |
| 预览字符串 == 词表期望 == SRT 04/05 | 自动 |
| 时延 p50/p95、峰值 RSS、空闲 CPU、线程数 | 自动（数字，需带负载标注） |
| 无解码子进程 / 无音频设备 / 换不可解码背景仍出字 / 重绘次数 | 自动 |
| 好看、清晰、字重协调、颜色舒服 | **只能 Tim 人眼** |

## 复用与代价

- 复用：`accept_range` 的分带/阈值/取帧、`load_expectations`、门禁的稳定证据目录与 stamp。
- 新增：一个离屏预览跑批脚本（不依赖 C 的界面，只要他能给"渲染到给定尺寸的画布"入口）
  + 一个审计钩子包装。
- 预计门禁增量：像素比对 < 10 s；时延/资源 5 次冷启动 ≈ 15–30 s（建议放**独立标记**
  `acceptance_preview`，因为它要弹离屏画布，和 headless 纯计算那条线分开）。
- **不做的**：不截屏真实桌面、不测"真实核显机"（那要目标机）、不把美感写成断言。
