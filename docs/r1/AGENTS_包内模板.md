# 项目执行规则（复制到真实仓库前核对现场路径，不覆盖已有规则）

## 核心工程原则

**从第一性原理出发，顾全大局，整体最优优先。** 先确定团队成员/Agent的真实目标、事实和约束，再选择最小充分方案；可靠复用，不做无依据的抽象、重复实现或推倒重写。

整体判断包含使用与返工、端到端等待、内存/计算/磁盘/TTS、可靠性、安全、开发与长期维护。不为单模块更快、更美或更少代码把成本转嫁给系统及成员；有依据的局部取舍可以接受，授权与已批准验收不可暗改。

H0每次派工传入本原则及整体目标，按依赖/关键路径编排；各角色只改任务相关内容，QA复核集成影响。重要取舍在已有提交/STATUS短记理由与验证；普通修复不增文档、审批或全量检查。合并到已有AGENTS时保留现场路径、命令和规则，不覆盖或重置进度。

- 当前顶层基线：2026-09-16 R1.1（原则补丁，继承R1范围）。Tim最新明确指示优先。只在指定D盘工作根内开发；默认模型，最多3开发+1QA，不递归派工。
- 根路径/目标仓库/真实TTS20000单位未确认前不猜；相关动作阻断，离线任务照常继续。
- 原字幕核心、原入口、旧归档受保护。迁入复制优先，不删原件；旧视频仅修允许的副本。系统改动/正式发布/签名另批。
- A：domain/application/storage/cli；B：media/voices/layout/exporters；C：desktop/preview/packaging/legacy_adapter；QA：独立验收；H0：依赖锁/根配置/集成/push。
- 小接口、一个工程、一个时间核心、共享应用命令；不造云/插件/MCP平台。默认单片段；三产物完整性和独立可编辑不降级。
- 所有应用测试默认无真实TTS网络/凭据；旧未公开内部配音路线不能作默认稳定能力；不替换声音/字体。
- 依赖/媒体/缓存/tmp/日志/输出默认D；子Agent不改共享环境；从各自worktree加载源码。用户数据不进GitHub。
- 哈希只在必要输入/资产/交付边界做；日常代码用Git。清缓存不删唯一配音/原件/工程/产物。
- 每变更附相关测试，修bug先留反例。不降低验收阈值、不用SKIP/旧PASS顶替。候选阶段测真实媒体与资源。
- 新增依赖、公共协议/架构变化需理由；小实现自主推进。未验如实写，不承诺绝对零bug。
- 每任务更新docs/STATUS一条；用户影响写CHANGELOG；改接口才改ARCHITECTURE。测试命令由H0按实际仓库填入下方，填好后运行。
