# 五阶段、十二任务与并行规则（R1.1）

**共同原则：从第一性原理出发，顾全大局，整体最优优先。** 所有W00–W11任务及A/B/C/QA均适用；分工只是协作边界，不是分别追求局部最优的理由。既有阶段、任务、并发上限和权限不变。

## 1. 不再用文档关卡阻塞一切

每阶段只有一个可运行结果；`实现/自动测试/实机操作/目标硬件/发布批准`分别标记。缺少一种证据，只阻止依赖它的能力和结论，不停止无关开发。阶段通过不需要Tim逐个小功能审批；涉及用户体验默认、重大路线和权限变化才问。

一次任务交付只需：**改了什么 → 测了什么及实际结果 → 未验证什么 → 下一步/回滚commit。** 自动测试日志保留一次，阶段汇总引用即可。Git commit和run_id够用的地方不另发契约哈希/全目录哈希清单。重要取舍在现有“改了什么”里补一句整体收益、主要代价和依据；普通修复不增加字段或报告。

## 2. 五阶段验收目标

| 阶段 | 用户能得到什么 | 必验标准 | 不能混同的情况 |
|---|---|---|---|
| P0 接管与安全起步 | D盘可运行开发工作区、旧成果迁入副本、离线测试入口 | 实际目录已绑定；未提交修改未丢；原字幕不变；相关依赖/临时文件在D；一个旧好样本及空批次/缺轨/错时/旧报告反例；默认测试零真实TTS调用 | GitHub未绑定只挡push；无第二台不挡开工；不强制全量复验旧七批 |
| P1 三词技术闭环 | 三词工程、连续预览、MP4/五SRT/草稿和目录式早期包 | 工程单一；默认单片段编辑/撤销/保存重开；真实媒体时长；文字/音频独立；三产物同计划；真剪映副本修改重开；无开发环境依赖的单机候选包 | 自动测试通过不等于剪映可编辑通过；没有真实低配机不宣称低配已验；可继续独立任务但不写正式合格 |
| P2 团队操作与Agent入口 | 成员用UI、Agent用CLI完成同一任务；方便复用声音 | 不手改JSON；缺媒体/字体/音色有可点修复动作；CLI plan/submit/status/cancel/resume；同键幂等；UI/CLI同revision；导入流程试听确认；旧字幕外层接入不改核心 | 导入音频不等于能合成新文字；未知版本草稿不冒充合格 |
| P3 50词批量与资源硬化 | 可恢复批量出片，空间/内存/CPU有界，版本可回滚 | 一组真实50词三产物；离线多包故障样本；只重做失败/变化部分；预算/UNKNOWN模拟；内存回收与长时压力；取消/崩溃/磁盘满；中文路径/无D盘/缺编码器；剪映更新复验流程 | 不要求开发者直接断生产机电；未做系统硬断电如实写未验；50词缺缓存需真实TTS批准后补 |
| P4 限定内部试用与发布准备 | 非开发成员独立操作、说明书、已知限制和恢复方案 | 至少1名真实成员在现有机器完成50词；严重数据丢失/静默错声错字/伪成功/泄密风险为零；版本和回滚清楚；Tim批准具体试用/发布范围 | 单机用户试用不是跨机验证；未签名明确显示；公开发布和正式签名另批 |

**精简旧线验证：**选一组已有可核对三词或一个旧批次作正常对照，加已知危险反例，不要求新开发前逐批完整重验全部旧归档。旧历史资料缺失写状态；不能伪造“已复验”。

P0以路径与保护、相关离线回归为完成条件；核心契约冻结并入W01，不单独造GC阶段。P1技术探针通过后再扩完整UI；旧线无实机证据不再成为新软件所有UI开发的硬前置，新软件自己的三产物实机证据仍需完成。

## 3. 三个开发角色 + 独立QA

| 角色 | 唯一写入主范围 | 负责的任务 |
|---|---|---|
| A 核心与自动化 | domain、application、storage、cli、公共契约 | W01、W05、W08 |
| B 媒体与交付 | media、voices、layout、exporters、迁入的旧视频修复副本 | W02、W03、W07 |
| C 桌面与发行 | desktop、preview、packaging、legacy_adapter | W04、W06、W09、W10 |
| QA 独立验收 | tests/acceptance、性能测试入口、验收结果 | W11，以及贯穿每次集成的反例 |
| H0 主控 | 根配置、锁文件、AGENTS、STATUS、集成分支与push | W00、派工、协调接口和合并 |

开发者可写本模块单测；QA不能为了通过而修改生产实现。公共schema由A单写，消费者用同一个版本。B需要一个UI页面时给C组件需求，不越界改desktop。一个角色不一定常驻一个子Agent；任务完成就结束，节省上下文与本机资源。

### 派工口径：目标指向完整生产流程

H0每次派工明确传入核心原则，并把现有“任务目标”写成“为团队成员/Agent解除什么生产阻塞，做到什么即可”，而不是只列要写的模块。按实际接口依赖和关键路径安排并行，不为了让全部Agent有活干而拆碎任务、制造等待或同时争用媒体资源。

任务仍沿用原卡，只在相关位置说明整体影响。例如：W03/W04共用布局，不能为了各自按期完成各做一套；W05/W08共享资源与缓存，不能以批量吞吐牺牲交互或重复请求；声音导入的成功标准是成员能完成复用，而不是只生成一份映射JSON。

| 角色 | 交付时必须同时考虑的整体影响 |
|---|---|
| A | 同一业务规则供UI/CLI及导出消费；接口复杂度、保存/幂等与局部复算不能让其他模块重复实现或成员额外操作 |
| B | 完整媒体/音频正确性、原生可编辑和端到端等待；局部提速不能换成重复TTS、无限缓存或额外磁盘副本 |
| C | 非开发成员可操作、核显资源、包装和故障恢复；不能把环境修复交给成员，或让视觉效果抢占生产资源 |
| QA | 固定输入下的完整UI/CLI生产、关键失败恢复与资源证据；不以测试数、单模块PASS或不可复现的性能数字替代可用性 |
| H0 | 集成后检查全流程、跨模块接口和资源分配；局部均通过但全局受阻时协调最小修复，不把问题甩给下一阶段 |

需要新增依赖、重复数据、额外并行或跨模块重构时，先问较简单方案是否足够，再说明实际收益及代价；有证据且在既有预算内的局部取舍可以接受，不擅自改已批准标准。不能证明需要的大改先不做，不能为了代码整洁顺便整理无关模块。

## 4. 每个任务的交付与验收

### W00｜迁入、D盘、Git与隔离（H0；无前置）

核对当前工作区、源路径、Git历史和未提交变化；按04选择性复制。做一次无害子Agent工作目录隔离探针。建立最少AGENTS/STATUS/环境锁定步骤，准备.gitignore。保持原件，新的开发只在根目录内。

验收：新旧入口有明确区分；源码/字幕核心迁入正确；依赖和新输出路径不依赖C盘工作树；旧媒体先按需导入，不全盘重复复制。目标仓库未定时有本地commit；确认私有目标后做内容/历史敏感项检查再push。没有路径不猜。

### W01｜唯一工程与编辑命令（A；W00）

先交消费者需要的Project/Clip/TimeExpr/MediaSlice/RenderPlan/CuePlan小接口和固定手算夹具，再实现求解、单片段/联动、撤销、保存重开和模板实例化。接口冻结指版本和字段稳定，不要求所有功能先完成。

验收：5.5秒算例；男声移0.2秒其他对象不动；教学重叠被拒绝；撤销恢复依赖；重复ID/环/悬空/未知时长/过期revision失败；模式切换不改业务；30/60及非整数帧率、44.1kHz源有正确换算。

### W02｜旧视频最小修复与媒体链（B；W00；消费W01最小接口）

复用已有合法缓存；补旧验收盲区所需生产侧修复；统一片头音轨策略，先完整加工再测长，分离原始TTS与加工缓存。新媒体接口支持有限音频重叠/音量、代理、实际PTS/样本；不把旧非重叠模型扩成新工程。

验收：正常缓存出片不联网；有/无声片头和外置音频不重复发声；变速不截尾/不双变速；修改字号不合成；修改速度仅加工；源音频重叠在基础混音可表达、教学策略独立阻断。旧字幕和旧归档保持不动。

### W03｜排版与三产物（B；W01、W02）

先给C稳定LayoutSurface/场景合成接口，再实现字体字形/溢出、画布字号与缩放、MP4/五SRT/剪映导出。MP4不经剪映GUI渲染。只支持本产品需要的图层与简单变换，不扩通用特效。

验收：真实三词，含IPA/长释义；全部角色文字与时间核对；首中尾和阶段切换帧；原生可编辑文字/各条配音/背景；副本打开→改词→移音标→换一条声→换背景→保存重开→导出。缺字/缺角色/不支持功能返回错误；三产物缺一不成功。

### W04｜连续预览（C；最终依赖W01–W03，接口冻结后可提前并行）

做独立画布、统一PCM时钟、源代理、generation seek、有限队列、明确过期状态。可先用测试布局适配验证时钟，但完成时必须接入W03真实排版，不能交两套布局实现。

验收：编辑不等整段重编码；缓存命中seek与起播达批准档目标；连续播放不混旧音；音频重叠、静音区、循环背景正确；反复打开关闭/定位资源释放。遇原生解码卡死有可恢复边界，不能无限join线程卡UI。

### W05｜协调器、存储和CLI（A；W01）

一个本机写者；原子保存/备份、任务双冻结、幂等收据、统一资源槽、进程回收；所有UI/CLI写操作共用命令。基础plan/submit/status/cancel/resume/artifacts在此实现，不等“最后接Agent”。

验收：两个客户端并发版本冲突正确；重复key不重复移动或发任务；修改原输入不污染旧任务；取消后不发布；晚到worker不能覆盖；CLI非交互、解析错误也有JSON；worker/主控终止后对账恢复。无法决定的错误返回NEEDS_INPUT，不弹窗口挂住Agent。

### W06｜成员可用的编辑器（C；W03、W04、W05）

模板/高级模式、默认单片段选中、独立拖动/修剪/拆分、字号/缩放/颜色/磁吸、锁定/隐藏/静音、保存重开。做输入预检与可点修复状态，优先正常成员上手而非玻璃装饰。

验收：三词从导入到三产物完整操作无需手改JSON；错误定位到词/片段并有恢复入口；多次模式切换不丢编辑；CLI改动在UI同步到同一revision。常用窗口、缩放和DPI可操作，不用逐像素UI截图代替业务测试。

### W07｜旧声音导入与音色扩展（B；W02、W05；界面由C在W06范围接线）

实现05的两类能力、向导后端与预设；已有媒体优先，按稳定ID/文字/角色/时段映射，只处理歧义；复用现有音色定义而非重新猜名字。正式API只在确认额度/权限后实调；音频导入和fake provider可先完成。

验收：三角色已有音频一批导入；重复导入不复制；错词/重复/缺失/跨账号音色不自动通过；全长混音不能冒充独立可编辑配音；“仅可复用/可合成/待验证/需要剪映操作”清楚。新文字合成与声音接近度需试音确认，不拿voice ID相同当证据。

### W08｜批量与可共享模板（A；W01、W03、W05）

固定record_id批次计划、每批独立实例；共享模板/资产、局部修改与应用全部明确；模板升级保手改、冲突可撤销；多包恢复只重做失败项。预先报告命中/缺失、费用单位、磁盘与目标兼容，Agent可无人值守处理已完备输入。

验收：真实50词单批三产物；另用便宜的离线多包样例测少包/漏最后一包/单批失败；编辑一词只影响该词需要的产物，不清全部缓存；模板包无密钥/绝对工作路径/脚本，能在换根路径副本导入。

### W09｜目录包、资源与恢复（C；W03、W04、W05）

在P1即交最小目录式包，然后在P3做完整资源/打包/更新回滚测试；不等UI全部完工才首次打包。只在D盘/已批准隔离位置操作，不装系统组件。依赖不进入C盘temp，不每次复制完整运行时给worker。

验收：当前机器隔离目录、开发路径不可依赖、中文/空格路径；无D盘明确选择其他数据盘不偷偷写C；可用编码器/字体诊断；资源指标与08反复操作；停止/取消/磁盘满/版本回滚。没有第二台写单机验证，不伪造跨机。

### W10｜旧字幕的轻量适配（C；W05、W06）

迁入已完成于W00；现在加新软件入口，通过独立子进程调用旧CLI/API，输出到D盘新目录。原核心及UI不改。不要因没有第二台电脑推迟一个可独立验收的适配器。

验收：相同词表/选区/分包/计时参数，新旧五SRT内容与毫秒时间等价；界面明确原文字规则计时与视频音频计时；新视频模块失败不使旧入口失效。

### W11｜独立验收与内部试用（QA；贯穿全部；最终依赖W06–W10及核心任务）

先写危险反例，再对集成commit跑；期望来自原词表、真实媒体和固定手算，不全用生产solve()生成。P3/P4跑08最小压力及单机试用。让真实非开发成员按说明完成任务，记录阻塞与人工分钟数，不承诺无证据的效率百分比。

验收：必测确实执行；没有样本/没有设备明确待验；报告不串旧run。最终交短说明：能用什么、哪里未验、怎么安装/回滚、谁完成了哪项。没有Tim发布批准就只提供候选包。

## 5. 建议并行波次

第一波：H0完成路径/隔离；A=W01；B=W02；QA=坏样本。C可读代码，不另开超过上限的写进程。

第二波：A=W05；B=W03；C=W04。接口先交小而稳定的一版，三者并行，不等待全部文档或全系统实现。

第三波：A=W08；B=W07；C先交W09早期包再推进W06。QA持续复验集成，真实剪映与性能测试独占资源。

第四波：C=W09硬化/W10；A/B修各自缺陷；QA=W11。没有第二台不阻断，但保留目标机器/跨机待验状态。

任务依赖以 `control/tasks.json` 为静态清单；W04可提前消费已冻结布局接口，W09有早期/最终两个检查点，不要求重复建包框架。阶段里不能为了凑并行硬拆互相改同一文件的任务。

## 6. 简单的开发纪律

每个Agent独立worktree与私有tmp；同一套锁定依赖只由H0改。若共用venv，禁止并发editable安装/依赖更新；从当前worktree显式加载源码。合并后QA在集成目录复跑，不能只相信各分支测试。

子Agent用默认模型，最多一级派发，停止后确认没有继续写入再回收目录。GitHub由H0统一push；不force push、不覆盖未提交用户工作，不自动开公开仓库。

任务结束不要求长证据包；真实高风险失败必须保留最小复现。只有改变存储主权、媒体后端、协议兼容、默认行为或权限才升级为顶层讨论。
