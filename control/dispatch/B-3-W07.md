## 1. 旧缓存导入（H0 已决定，理由：Tim 定"优先已有音频"）

- 输入：旧缓存根目录（例如 `D:\单词速记自动化_测试归档_0915\*\wv-*\audio-cache`）
  + 词表 + 选区 + 角色/音色要求。
- 匹配：按**内容身份**（角色 + 规范化文字 + 音色）匹配 `original.*` 文件；
  **歧义（同一角色同文本多条不同音色）不要自动选**——列出来让人确认，或按明确指定的音色取。
- 产出：把这些原件作为 `provider.kind=local` 的输入喂给引擎，**由引擎自己重新测长并变速加工**；
  **禁止**直接信任旧 `complete.json` 的 `raw/rendered`（已知它与原件真实时长不符）。
- 硬指标：**导入过程 TTS 调用数 = 0**（用假 provider 或计数把守断言，别用"我没看到调用"当证据）；
  重复导入不复制文件、不产生第二份音频（同一素材入库一次，之后按 asset id 引用）。
- 判据：导入后跑一次真实三词或 50 词，产出与"手工按夹具喂原件"的结果一致
  （可用 `tools\compare_batches.py` 与 `D:\单词速记自动化_测试归档_0915\范围151-200-切片渲染\...\0151-0200` 对照，
  H0 实测该路径可逐帧复现）。

## 2. 旧剪映配音/音色导入流程

- 成员能选一个旧剪映草稿/资源目录，软件列出可用的配音与音色，**支持试听**，
  成员确认后写入音色预设；成功后能直接用于新工程。
- 已有的音色定义**复用**，不要重新猜名字；导入音频 ≠ 获得新文字合成能力（界面与文档都要说清）。
- 状态要分清：**仅可复用 / 可合成 / 待验证 / 需要剪映操作**。
- 全长混音**不能**冒充"独立可编辑配音"。
- 未公开的内部配音通道只用于**风险识别**：不把固定客户端身份或内部端点做成团队默认能力。

## 验收（必须真跑并贴结果）

1. 三角色各导入一批真实旧音频：给出实际条数、匹配成功/歧义/缺失数，以及你如何处理歧义。
2. 重复导入：第二次导入的文件数与磁盘占用不增长（贴数字）。
3. 错词 / 重复 / 缺失 / 跨账号音色：**不自动通过**，给明确错误或待确认状态（各给一个最小反例）。
4. 导入后真实出片一次（三词即可）并对照归档；TTS 调用数 = 0 的证据。
5. 试听与"仅可复用/可合成/待验证/需要剪映操作"的判定表（举至少 4 个真实样本）。
