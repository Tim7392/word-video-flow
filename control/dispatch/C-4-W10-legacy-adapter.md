## 为团队解除什么阻塞

成员现在有两套东西：**旧字幕工厂**（`Words_SRT.py` / `subtitle_factory_cli.py`，受保护、还在用）
和**新软件**（工程模型 + 三产物）。如果不做适配，成员要在两套入口之间手工搬词表、
对时间、比字幕——这正是"更少操作"要消掉的东西。本任务给旧字幕一个**新软件入口**，
但**不许改旧核心**。

## 可改范围（白名单）

- 编辑器里为它加一个入口（`desktop/**`，最小改动）
- **禁止改**：根目录旧字幕工厂 6 个文件（`subtitle_factory_*.py`、`Words_SRT.py`、`word.py`）、

  `AGENTS.md`、`control/**`、`docs/**`、其他 worktree、旧归档

## 要求

1. **独立子进程**调用旧 `subtitle_factory_cli.py`（或旧 API），工作目录与输出都在 **D 盘新目录**下；
   不导入旧模块进新进程、不改旧文件、不写旧输出目录。
2. **界面/入口必须区分两种计时口径**：
   - 旧口径：按**文字规则**（字数/词性/中文下限）推时长；
   - 新口径：按**视频音频实际时长**（`timeline.json` / 计划）。
   用户必须一眼看出当前用的是哪一种，避免把两套时间混着对外交付。
3. **失败隔离**：新视频模块（渲染/预览/打包）失败**不能**让旧入口失效；反之亦然。
   两边的错误都要结构化、能定位（沿用现有 code 风格）。
4. **等价性验收（本任务的硬指标）**：同一词表 + 同一选区 + 同一分包/计时参数下，
   **新旧五轨 SRT 的内容与毫秒时间等价**。等价口径要写清：文本逐字节相同、
   时间按毫秒相同（或给出你证明过的容许差并解释来源）。用真实归档做对照。
5. 不为适配器发明第二套业务：参数映射、词表读取、分包规则都必须复用现有实现。

## 验收（必须真跑并贴结果）

1. 用 `D:\单词速记自动化_测试归档_0915` 里的一批真实数据：旧入口产出 vs 新入口产出，
   五轨 SRT 逐字节/逐毫秒对照表（不一致的必须逐条解释，不能"差不多"）。
2. 旧入口失败 / 新入口失败各自的最小反例：证明互不拖累。
3. 时间口径提示的可见性证据（界面文本或 CLI 字段，含两种口径的实际数值）。
4. 全程未修改旧字幕工厂 6 文件（`git diff --name-only` 为空）与旧归档（mtime/哈希核对）。
