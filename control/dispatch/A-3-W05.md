## 交付物

1. **本机单写者协调器**：所有写入经过同一入口；并发客户端版本冲突要**正确报错**而不是互相覆盖；
   原子保存 + 备份；无任务时不占重型 worker（按需启动）。
2. **任务双冻结与幂等收据**：提交时固定"工程/输入意图"（工程 revision + 输入指纹），
   媒体就绪后再固定"实际音频/计划"；`idempotency_key` 重复同请求返回原任务，不同内容冲突；
   重试已完成项**不重复扣费、不覆盖成果**；取消后不发布；晚到的 worker 不能覆盖新结果。
3. **CLI（Agent 自动化是首版能力）**：`capabilities`、`doctor`、`project`/`voice`/`template`、
   `batch plan`/`batch submit`、`job status|cancel|resume`、`artifacts`。
   - stdout **单个 JSON**，日志走 stderr；`watch` 另用 NDJSON；
   - 合法请求、无效参数、后台失败都要结构化错误（含错误类型与可执行修复项）；
   - 默认 non-interactive **不弹对话框**，缺信息返回 `NEEDS_INPUT`；
   - `plan` 只预检/估算（不合成、不发布）；`submit` 需要 idempotency key + 固定计划/工程版本 + 有效 TTS 权限。
   - **先完成 CLI，不要造云 API/MCP 平台**。
4. **SQLite 只存任务/索引/收据**，不另存一份可编辑工程；工程真相仍是 `project.json`。

## 验收（必须真跑并贴结果）

1. 两个客户端并发提交/保存：正确的一个成功、另一个得到明确冲突错误（贴两边输出）。
2. 同键同请求 → 返回原任务（同 job id）；同键不同内容 → 冲突；重试已完成任务 → 不重复执行。
3. 修改输入文件后旧任务不受影响（输入指纹固定）；取消后不发布任何正式产物。
4. worker 或主控被强杀后：对账能恢复/标记，不出现"半个产物被当成功"。
5. CLI：无参数/错参数/未知子命令 → stdout 仍是合法 JSON + 非零退出码；`plan` 不产生任何媒体文件；
   `NEEDS_INPUT` 场景给出可执行修复项。
6. 幂等/收据在**同一 SQLite 内**可核对（贴表内容或查询输出）。
